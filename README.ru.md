# ArchitectSkill

**architect** — скилл для Claude Code: «планируй дорого, исполняй дёшево».

[English](README.md) · Русский

> ## ТОЛЬКО ДЛЯ ДЕСКТОПНОГО ПРИЛОЖЕНИЯ
> Скилл рассчитан **только на десктопное приложение Claude Code (Windows и macOS), вкладку Code.**
> Он **НЕ** для терминального `claude` CLI, расширений VS Code / JetBrains, чата claude.ai в
> браузере, ChatGPT и любых других моделей и продуктов.
>
> Причина: фаза параллельных сессий (шаг 5) использует инструменты, которые есть только в
> десктопном приложении: `spawn_task`, `list_sessions`, `set_session_model`,
> `set_session_effort`, `get_session`, `send_message` / `SendMessage`.
>
> Разработан и проверен на Windows. На macOS должен работать так же, отличаются только пути
> установки.

## Что делает

**Проблема.** Когда одна сильная модель делает всё подряд (читает код, гоняет тесты, правит
мелочи), токены и лимиты подписки уходят на рутину, где сила не нужна. А большая задача в одной
длинной сессии раздувает контекст.

**Что делает скилл — три вещи:**

1. **Разделяет роли между моделями.** Самая сильная из ваших моделей только думает: разбирает
   задачу, пишет план, ставит задания, проверяет результат по diff. Рутину делают модели
   подешевле, а тесты перед слиянием всегда гоняет отдельный исполнитель.
2. **Разделяет большие задачи на сессии.** Оценивает задачу и предлагает в плане: оставить всё
   в одной сессии, вынести независимые части в параллельные или пустить цепочку сессий, если
   куски идут друг за другом. Ничего не запускается без вашего подтверждения.
3. **Делает аудит проекта и предлагает, как тратить меньше.** Смотрит на инструкции
   (`CLAUDE.md`, `MEMORY.md`, большие гайды), показывает, что жжёт токены в каждой сессии, и
   предлагает сжать текст, перевести инструкции на английский, разбить огромные гайды на блоки,
   чтобы агент читал только нужное. Без вашего согласия ничего не меняется.

Модели в таблице ниже — пример связки автора; используйте те, что у вас есть.

| Роль | Модель / effort | Задача |
|---|---|---|
| Архитектор | Fable 5.1, `medium` | План, брифы, ревью диффов, интеграция. Сам код не изучает и не пишет. |
| Исполнитель (сложное) | Opus 5, `high` | Неизвестная причина, инварианты, куски, которые не расписать жёстко. |
| Исполнитель (по умолчанию) | Sonnet 5, `high` | Механика, рецепты, тесты, документы, переводы, чётко описанные правки. |
| Тестировщик | Sonnet 5, `high` | Всегда гоняет проверки перед слиянием. Только запускает и докладывает, ничего не чинит. |

Скилл включается **только по явному вызову**, сам не активируется.

## Требования

- **Десктопное приложение** Claude Code, Windows или macOS, вкладка **Code**.
- Доступ к моделям из таблицы (нет Fable — см. ниже).
- `git` либо просто ZIP-архив.

## Установка

Корень репозитория и есть папка скилла. Клонируйте её в каталог скиллов под именем `architect`.

Windows (PowerShell):

```powershell
git clone https://github.com/mrgnfndr-dr/ArchitectSkill "$env:USERPROFILE\.claude\skills\architect"
```

macOS:

```bash
git clone https://github.com/mrgnfndr-dr/ArchitectSkill ~/.claude/skills/architect
```

Или скачайте ZIP с GitHub и скопируйте папку в `<you>\.claude\skills\architect` (Windows) либо
`~/.claude/skills/architect` (macOS) так, чтобы `SKILL.md` лежал прямо внутри. Если скилл не
появился в списке — перезапустите приложение.

## Вызов

Во вкладке Code:

```
/architect
```

Также срабатывает: «архитектор», «режим архитектора», «распиши план и исполнителей»,
"architect", "architect mode". Отвечает скилл на том языке, на котором вы пишете.

## Что происходит при первом запуске в проекте

Перед планом `architect` ищет отметку «architect token audit done <дата>» (заметка в памяти
проекта или файл `Research/architect/AUDIT.md`, если памяти нет).

- **Отметки нет:** субагент Sonnet 5 измеряет ваши всегда загружаемые инструкционные файлы, не
  читая их целиком: все `CLAUDE.md`, индекс `MEMORY.md`, гайды, которые агенты читают перед
  каждой задачей. Дополнительно отмечает скиллы и MCP-серверы, которыми проект не пользуется
  (справочно; отключить их можете только вы).
- Вы получаете одну таблицу `файл | размер сейчас | доля кириллицы | проблема | что предлагается |
  оценка после` и 3–4 строки итога (см. `templates/AUDIT-REPORT.md`). Оценки токенов
  приблизительные: кириллица в UTF-8 стоит примерно на 40–50% больше токенов, чем тот же
  английский текст.
- Варианты: сжать (правила остаются, история уходит в `docs/rules-history.md`), перевести
  инструкционные файлы на английский, разбить огромные гайды на индекс и файлы по темам.
- **Это предложение, а не барьер.** Отказались — работа продолжается, отказ записывается и не
  поднимается снова, пока файлы не вырастут более чем на 25%. Без вашего подтверждения ничего не
  меняется. Согласились — сжатие идёт с независимым аудитом после каждого этапа.
- Отметка есть: только дешёвая проверка размеров; полный повторный аудит — если файлы выросли
  более чем на 25% или вы попросили «аудит токенов».

## Модели: настройте под себя

Рекомендуемая связка: архитектор Fable 5.1 на `medium`, исполнители Opus 5 и Sonnet 5 на
`high`. Идентификаторы моделей и уровни effort — значения автора по умолчанию, поменяйте их в
`SKILL.md` по вкусу. Нет доступа к Fable — используйте Opus 5 как архитектора.

## Когда не нужен

Тривиальные задачи в одно предложение и один рецепт: откройте сессию на Sonnet напрямую.
Архитектор тут только накладные расходы — скилл сам об этом скажет.

## Шаги

0. Аудит токенов при первом запуске и гигиена инструкционных файлов.
1. Оценка задачи и выбор ступени: один субагент, один контур с несколькими субагентами,
   параллельные сессии, последовательная цепочка с файлом передачи.
2. Разведка делегируется агенту Explore/Sonnet; выводы на одну страницу.
3. План вам на подтверждение; до вашего подтверждения ничего не запускается.
4. Брифы (`templates/BRIEF.md`): самодостаточные, шесть пунктов, на английском.
5. Параллельные сессии для больших задач: сначала файл-контракт (`templates/CONTRACT.md`),
   затем двухфазное создание сессий, чтобы модель и effort реально применились, затем
   интегратор. Если этих инструментов нет в вашей версии приложения, скилл работает только
   субагентами. Цепочка — через `templates/HANDOFF.md`.
6. Ревью: читается диф, отчёту не верят; дефекты возвращаются тому же исполнителю.
7. Тесты перед слиянием: всегда отдельный тестировщик Sonnet 5; затем одно слияние — только с
   вашего согласия.

Пример полного (вымышленного) прогона: `examples/walkthrough.md`.

Правила вашего проекта (`CLAUDE.md`: ветки, деплой, деньги, удаление данных) всегда главнее
скилла.
